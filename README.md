# ziovpontvrs

## Сборка

Требуется MinGW-w64 и утилита `widl` (генератор RPC-стабов, входит в пакет
`mingw-w64-tools`).

```bash
cmake -B build -DCMAKE_TOOLCHAIN_FILE=cmake/toolchain-mingw64.cmake
cmake --build build
```

Результат: `build/ziovpontvrs.exe` (GUI) и `build/ziovpontvrs_svc.exe` (сервис).

## Установка через инсталлятор

Скачайте `ziovpontvrs-setup.exe` из артефактов сборки и запустите от имени
администратора. Инсталлятор:

- Копирует `ziovpontvrs.exe` и `ziovpontvrs_svc.exe` в выбранную директорию
- Устанавливает Visual C++ Redistributable, если отсутствует в системе
- Регистрирует Windows-службу `ZiovpontvrsSvc` с автоматическим запуском
- Запускает службу
- Создаёт запись в «Установка и удаление программ»

При удалении через «Установка и удаление программ» инсталлятор:

- Останавливает и удаляет службу из диспетчера служб
- Удаляет Visual C++ Redistributable, если он был установлен инсталлятором
  и не используется другими приложениями
- Удаляет все файлы приложения
- Удаляет записи из реестра

### Сборка инсталлятора локально

```bash
sudo apt-get install nsis
cp build/ziovpontvrs.exe build/ziovpontvrs_svc.exe installer/
makensis installer/ziovpontvrs.nsi
```

Результат: `installer/ziovpontvrs-setup.exe`.

### Сборка на CI

Инсталлятор автоматически собирается на конвейере GitHub Actions и
выкладывается в артефакты сборки (`ziovpontvrs-installer`).

## Ручная установка сервиса

Из командной строки с правами администратора:

```cmd
ziovpontvrs_svc.exe install
```

Сервис зарегистрируется с автоматическим запуском.

Для удаления:

```cmd
ziovpontvrs_svc.exe uninstall
```

## Архитектура

### Межпроцессное взаимодействие

Сервис и GUI общаются через **Windows RPC** с транспортом **ALPC**
(`ncalrpc`). IDL-файл: `src/rpc_iface.idl`, общие настройки транспорта —
`src/rpc_common.h`. Интерфейс состоит из методов управления, аутентификации,
лицензирования и антивирусного гейта:

| Метод | Назначение |
|-------|-----------|
| `RpcShutdown`          | Остановка сервиса                              |
| `RpcLogin`             | Аутентификация пользователя                    |
| `RpcLogout`            | Выход из учётной записи                        |
| `RpcGetCurrentUser`    | Текущий аутентифицированный пользователь       |
| `RpcGetLicenseStatus`  | Метаданные лицензии (наличие, срок действия)   |
| `RpcActivateProduct`   | Активация продукта по коду                     |
| `RpcAntivirusScan`     | Запуск сканирования (блокируется без лицензии) |

JWT-токены и сырой лицензионный тикет **никогда** не покидают процесс
сервиса — RPC возвращает клиенту только метаданные (логин, «есть ли
лицензия», дата истечения).

### Графическое приложение (`ziovpontvrs.exe`)

- При старте проверяет состояние сервиса. Если тот остановлен — запускает
  его и ждёт состояния `Running`, после чего завершает работу.
- Проверяет родительский процесс: если это не `ziovpontvrs_svc.exe`,
  приложение немедленно завершается.
- Главное окно при старте скрыто. Показывается автоматически, только если
  требуется действие пользователя (логин или активация).
- **Страница логина** — если RPC сообщает, что пользователь не
  аутентифицирован. Ошибка логина выводится под кнопкой и форма остаётся
  на экране.
- **Страница активации** — если пользователь есть, но лицензии нет. Поле
  ввода кода активации и кнопка «Активировать». При ошибке — сообщение и
  форма остаётся на экране.
- **Dashboard** — если есть лицензия. Показывает логин, дату истечения
  лицензии и кнопку «Запустить сканирование».
- Раз в 15 секунд опрашивает сервис через `RpcGetLicenseStatus` и
  перерисовывает текущую страницу; при смене статуса (например, лицензия
  истекла или активирована из другого места) окно поднимается.
- Меню **Файл → Выход** и пункт **Выход** в трее останавливают сервис
  (через `RpcShutdown`). Меню **Аккаунт → Выйти из аккаунта** вызывает
  `RpcLogout`.

### Сервис (`ziovpontvrs_svc.exe`)

- Регистрируется как служба Windows с автоматическим запуском.
- При старте запускает `ziovpontvrs.exe --silent` во всех активных
  терминальных сессиях (кроме сессии 0) от имени владельца сессии.
- Отслеживает события `WTS_SESSION_LOGON` и запускает GUI в новых сессиях.
- **Не принимает** управляющие сигналы `SERVICE_CONTROL_STOP` и
  `SERVICE_CONTROL_SHUTDOWN`. Остановка возможна только через RPC-метод
  `RpcShutdown`.
- Запускает RPC-сервер на ALPC-эндпоинте `ZiovpontvrsRpcEndpoint` и
  блокируется в `RpcServerListen` до тех пор, пока клиент не вызовет
  `RpcShutdown`.
- При остановке завершает все запущенные им GUI-приложения через
  `TerminateProcess`.

### Аутентификация и лицензирование

- HTTPS-запросы к Web-сервису идут через **WinHTTP** (`src/http_client.*`),
  эндпоинты в `src/api_config.h`.
- Полученный JWT-Access и JWT-Refresh хранятся только в памяти процесса
  сервиса (`src/auth_state.cpp`). Логин → POST `/api/auth/login`; обновление
  → POST `/api/auth/refresh`.
- Фоновый поток обновляет оба токена заранее (по `exp` из JWT минус
  `API_REFRESH_SKEW_SEC`).
- Лицензионный тикет запрашивается через `/api/license/status` (Bearer),
  активация — через `/api/license/activate`. Если эндпоинт активации
  возвращает ответ без тикета, сервис сразу делает запрос статуса.
- Отдельный фоновый поток обновляет тикет по его сроку действия.
- При потере лицензии фоновые антивирусные задачи останавливаются, а RPC
  методы, связанные с антивирусом (`RpcAntivirusScan`), возвращают код
  ошибки `kErrLicenseMissing`.
- Ни JWT-токены, ни тикет никогда не записываются на диск.
